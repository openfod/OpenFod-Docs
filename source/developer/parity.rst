Parity 对照
===========

规则层正在重写。旧工程保持可运行，是唯一完整的行为对照，所以它是 oracle。两套引擎不能链进同一个测试进程——类型同名会碰撞——而且旧测试套件编译的是旧接口。重写一旦开始，那些测试就不再能当规格。

做法（ADR 0005）：**不要链接两套引擎。分开驱动，对比 transcript。**

::

   scenario.json  ──►  旧引擎 runner  ──►  transcript.reference.json  ─┐
        │                                                              ├─► diff
        └──────────►  新引擎 runner  ──►  transcript.new.json         ─┘

约定
----

- **场景是数据不是代码。** JSON 描述地图、刷兵、带时间戳的命令和要跑多久。场景里不出现 C# 类型名，这样架构重写不会毁掉规格。
- **Transcript 是规范投影。** 每个观察到的 tick 一条记录，单位按 id 排序，字段顺序固定，LF 换行，无时间戳。同一引擎跑两次必须字节级一致，否则 oracle 是噪声。
- **Diff 必须写明容忍项。** 差异要么报出来，要么列出容忍理由。被容忍的差异是记录在案的分叉。
- 两个 runner 只共享场景模型和 transcript 模型。

``parity/`` 是过渡目录。等价性成立之后应当删除，而不是永远堆着两套世界。
